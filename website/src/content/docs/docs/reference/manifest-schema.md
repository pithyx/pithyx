`pithyx.json` at the root of an app package is validated against one JSON Schema (draft 2020-12): `sdk/schema/manifest.v1.schema.json` in the repository, published as `@pithyx/sdk/schema/manifest.v1.schema.json` and identified as `https://pithyx.org/schema/manifest.v1.schema.json`. The box, `pithyx validate` and the TypeScript types of the SDK all read this file. The tables below are generated from it each time the site is built; how the fields work together is explained in [The manifest](/docs/developers/apps/manifest/).

Unknown fields are errors everywhere. The schema is a stable contract: a new optional field is a minor change, anything else a major one. A violation is reported as [`app.manifest.schema_violation`](/docs/reference/errors/#app.manifest.schema_violation) with the JSON pointer of the field. Beyond the schema the box checks the id ([`app.manifest.id_invalid`](/docs/reference/errors/#app.manifest.id_invalid), [`app.manifest.id_reserved`](/docs/reference/errors/#app.manifest.id_reserved)), the version ranges, that `window.minSize` fits into `window.defaultSize`, duplicates and references between fields, the cron expressions and the elevated rights ([Findings](/docs/reference/cli/findings/#app-packages)).

Paths use `.` for nested fields, `[]` for the entries of an array and `<name>` or `<language>` for keys you choose. "Required" is relative to the enclosing object: `backend.compose` is required when there is a `backend`.

## Related schemas

In the same folder: `compose.v1.rules.json` (the [Compose rules](/docs/reference/compose-rules/)), `images-lock.v1.schema.json` (`backend/images.lock.json`), and the catalog formats `catalog.v1.schema.json`, `index.v1.schema.json`, `index-signature.v1.schema.json`, `maintainers.v1.schema.json` and `catalog.v1.rules.json`.
