`pithyx.json` im Wurzelordner eines App-Pakets wird gegen ein einziges JSON-Schema (Draft 2020-12) geprüft: `sdk/schema/manifest.v2.schema.json` im Repository, veröffentlicht als `@pithyx/sdk/schema/manifest.v2.schema.json` und identifiziert als `https://pithyx.org/schema/manifest.v2.schema.json`. Die Box, `pithyx validate` und die TypeScript-Typen des SDK lesen alle diese Datei. Die Tabellen unten werden bei jedem Build der Website daraus erzeugt; die Beschreibungen kommen aus dem Schema und sind deshalb englisch. Wie die Felder zusammenspielen, erklärt [Das Manifest](/de/docs/developers/apps/manifest/).

Unbekannte Felder sind überall Fehler. Das Schema ist ein stabiler Vertrag: Ein neues optionales Feld ist eine Minor-Änderung, alles andere eine Major-Änderung. Ein Verstoß wird als [`app.manifest.schema_violation`](/de/docs/reference/errors/#app.manifest.schema_violation) mit dem JSON-Pointer des Felds gemeldet. Über das Schema hinaus prüft die Box die ID ([`app.manifest.id_invalid`](/de/docs/reference/errors/#app.manifest.id_invalid), [`app.manifest.id_reserved`](/de/docs/reference/errors/#app.manifest.id_reserved)), die Versionsbereiche, ob `window.minSize` in `window.defaultSize` passt, Duplikate und Verweise zwischen Feldern, die Cron-Ausdrücke und die erweiterten Rechte ([Befunde](/de/docs/reference/cli/findings/#app-pakete)).

Pfade nutzen `.` für verschachtelte Felder, `[]` für die Einträge eines Arrays und `<name>` oder `<language>` für Schlüssel, die du wählst. "Pflicht" bezieht sich auf das umgebende Objekt: `backend.compose` ist Pflicht, wenn es ein `backend` gibt.
